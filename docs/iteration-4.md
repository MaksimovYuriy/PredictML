# Итерация 4: универсальные таблицы и сохраняемая предобработка

Реализован отдельный сценарий predictml/tabular: чтение CSV/XLSX, список листов, предпросмотр, конфигурация цели/признаков/исключений/типов, train-only предобработка и загрузка сохранённой модели. CLI дополнен inspect-table, train-table и predict-table. Сценарии материалов и цены сохраняют существующие команды.

Общий цикл оптимизации MLP вынесен в training.fit_arrays. Старые fit и новый табличный сценарий используют одну реализацию обучения. Исходные reference-тесты по-прежнему проверяют совпадение весов/метрик в legacy-parity; спрос demand-v2 сохраняет рекурсивную validation-оценку.

Статистики imputer/scaler и категории кодировщика обучаются только на train. Типы без явного override тоже определяются по train, не по всей таблице. Входной размер MLP зависит от результата предобработки. Схема и обученный конвейер сохраняются вместе с весами в joblib. Неизвестные категории дают нулевой блок; порядок входных столбцов восстанавливается по именам, пропущенные столбцы не создаются молча.

Общий временной режим требует явных частоты/горизонта/определения подготовленной цели и декларации доступности признаков. Он разделяет данные по датам origin и исключает строки с ещё неизвестной к границе следующего раздела целью. Цель не сдвигается автоматически, общая рекурсия/групповые лаги не добавлены. Подробности: tabular-contract.md.

Добавлены синтетические примеры examples/tabular: housing.csv и XLSX с листами about/training, новые данные без цели, конфигурация; второй пример monthly.csv с явно подготовленной временной целью. Это учебные данные, не реальные цены или спрос.

Зависимости: добавлены scikit-learn, openpyxl и joblib; зафиксированы проверенные версии и их новые транзитивные зависимости. Исправлено прежнее противоречие pandas<3 в pyproject и pandas==3.x в requirements. Минимум Python для текущего проверенного набора установлен 3.12: закреплённые numpy/scipy требуют его. Полный переносимый lock всех зависимостей PyTorch и приёмка Windows остаются этапом 9.

Проверки покрывают две разные схемы, train-only статистики и словарь, неизвестные категории, полностью пустые признаки с явным типом, удаление отсутствующих целей, отказ для ошибочных целей/чисел/дат/схем, CSV/XLSX и листы, дубликаты заголовков, прогноз в новом процессе из joblib, хронологическое разбиение и исключение пересекающихся горизонтов. Проверки качества MLP не утверждают, что она превосходит альтернативы: сравнение моделей — следующая итерация.

Итог: pytest — 31 passed в текущем Linux/CPU-окружении, включая все 23 проверки предыдущих итераций. Зависимости тестов/таблиц установлены во временный каталог /tmp/predictml-iteration4-deps, запуск использовал соответствующий PYTHONPATH. Дополнительно через CLI обучены housing из именованного листа XLSX и monthly из CSV (по 50 эпох), выполнены предпросмотр и отдельный predict-table в XLSX. Это не приёмка чистого окружения и не проверка Windows. Следующая итерация — 5: baseline, линейная модель, MLP и единое сравнение.
