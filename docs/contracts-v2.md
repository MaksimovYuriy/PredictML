# Контракт месячного спроса v2

Применяется в режиме demand-v2, который является режимом по умолчанию с итерации 3. [Контракт v1](contracts.md) остаётся описанием legacy-parity.

## Сырой экспорт

Те же четыре CSV, что в v1. В materials.csv дополнительно обязательны unit (непустая строка) и purchase_step (конечное число >0). quantity, minimal_quantity и required_quantity теперь допускают дробные значения ≥0. Норматив расхода имеет единицу unit материала на одну завершённую запись; цена — за единицу. Идентификаторы по-прежнему положительные целые, все внешние связи проверяются.

Дата as-of исключает свой календарный месяц целиком. Все строки будущих месяцев и неполного месяца не участвуют в подготовке. Нулевые месяцы восстанавливаются из сырого экспорта по общей календарной сетке; отсутствие записей трактуется как нулевой спрос. Для реальных экспортов источник должен гарантировать полноту выгрузки.

## Подготовленные файлы

- monthly_demand.csv: service_id, year, month, total_bookings. Непустая таблица, целочисленные ID/календарь/число записей ≥0. У каждого service_id одинаковая непрерывная сетка месяцев без дубликатов. Для прогноза требуется минимум четыре месяца, для обучения — минимум десять.
- preparation.json: mode=demand-v2, contract_version=2, frequency=MS, group_column=service_id, target=total_bookings, as_of, first_month, last_complete_month, includes_partial_month=false, horizon_max=3 и missing_month_policy=zero. Последний месяц таблицы должен быть непосредственно перед месяцем as_of.
- materials.json: массив объектов id, title, current_quantity, minimal_quantity, price, unit, purchase_step. Числовые величины конечны и ≥0; purchase_step строго >0. Денежные/количественные значения могут быть десятичными строками для точного Decimal-представления. ID — JSON integer, названия и unit — строки.
- service_materials.json: массив service_id, material_id, required_quantity. Связи должны принадлежать моделируемому набору услуг и справочнику материалов. Повторные нормы суммируются, как в исходном контракте.
- price_analysis.csv: формат v1; подготовка ограничена полными месяцами. Это отдельная рекомендация цены.

## Прогноз и результаты

`--months` — целое 1, 2 или 3. Прогнозируется ожидаемое количество завершённых записей отдельно по service_id. Оно может быть дробным и ограничивается снизу нулём.

- demand_predictions.json/CSV: service_id, year, month, lead, predicted_bookings; lead=1 — месяц сразу после последнего наблюдаемого.
- material_predictions.json: поля v1 плюс unit и purchase_step; расчёт закупки использует Decimal и округление количества вверх по шагу, денег HALF_UP до двух знаков. Остаток и минимальный запас учитываются один раз за горизонт.
- demand_test_predictions.csv: model, origin, service_id, year, month, lead, actual, predicted_bookings для MLP и двух baseline в одном фиксированном окне test.
- material_metrics.json: one_step, recursive_test, recursive_validation, best_val_loss, validation_policy, split, units. Каждая метрика в количестве записей (MSE — квадрат единиц), wMAPE — в процентах. null у wMAPE означает нулевую сумму |фактов|; null у R² означает менее двух наблюдений либо постоянную цель.
- material_model.pth: общие поля MLP плюс demand_context со схемой v2 и агрегированной историей. Статистики признаков фиксированы на train.

Для повторного прогноза можно подать каталог только с двумя JSON-справочниками: история берётся из checkpoint. При наличии monthly_demand.csv обязательны metadata и сохранённый исторический префикс без изменений; новые полные месяцы дописываются для того же набора услуг. Использование ratio-весов v1 в этом режиме запрещено: нужно выбрать legacy-parity или обучить новую модель.
