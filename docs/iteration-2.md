# Итерация 2: общее ядро

Статус: реализована. Методика исходных сценариев сохранена.

## Изменения

- models/mlp.py: одна MLP, вход определяется числом преобразованных признаков, архитектура задаётся конфигурацией. Имена net.* в state_dict сохранены.
- config.py: неизменяемые конфигурации сценариев и обучения. Исходные архитектуры, число эпох, dropout, Adam и интервал проверки validation сохранены по умолчанию.
- training.py: общее обучение, нормировка по train, выбор лучших весов, метрики и baseline. Различия календарных разбиений спроса и цены сохранены явно. fit возвращает checkpoint и не пишет файлы.
- metrics.py: общие исходные MSE/MAE/wMAPE. Старое поведение при нулевом знаменателе пока сохранено для совместимости.
- inference.py: независимый Predictor с собственными весами, нормировкой и списком признаков; загрузка на CPU. Проверяются размеры и корректность статистик.
- scenarios/materials.py и price.py: предметные преобразования и постобработка; функции принимают таблицы, справочники и Predictor явно.
- pipeline.py: оркестрация, валидация и запись файлов. Нет импорта legacy, подмены путей или параметров чужих модулей. Входная таблица используется из валидатора без повторного чтения CSV.
- Исходные четыре скрипта перемещены из predictml/legacy в tests/reference/python; рабочий пакет от них не зависит. CLI и имена выходных файлов сохранены.

Небольшие изменения границ API: неверный порядок признаков checkpoint явно отклоняется, некорректные размеры и статистики не проходят загрузку. Epochs должны достигать хотя бы одной проверки validation; нечисловая validation loss даёт понятную ошибку. Загрузка исходных весов использует map_location=cpu. Консольные подробные логи исходных скриптов не воспроизводятся, результаты остаются в файлах и возвращаемом значении API.

## Проверки

Для обоих сценариев исходные и новые тренеры запускаются на одной синтетической таблице с одинаковым seed и 50 эпохами. Сравниваются все поля checkpoint, все тензоры весов (точное совпадение в текущем CPU-окружении), метрики и итоговые прогнозы. Сохранённые исходным тренером веса применяются новым конвейером без конвертации. Сравнение forward отдельно подтверждает совместимость архитектур.

Параллельно выполняются три прогноза с разными моделями/сценариями/горизонтами и каталогами; результаты совпадают с последовательными вызовами. Полная воспроизводимость параллельного обучения не заявляется: генератор случайных чисел PyTorch остаётся общим. Каталог результатов каждого вызова должен быть отдельным.

Методические ограничения намеренно не исправлены: среднее спроса по всей истории, включение неполного месяца, различия тренда обучения/прогноза, относительные метрики, усреднение признаков последнего года для рекомендации цены. Они не скрыты внутри рефакторинга и остаются задачами последующих итераций.

Прямой API ядра:

```python
from predictml.config import MATERIALS, TrainingConfig
from predictml.training import fit
from predictml.inference import Predictor

checkpoint = fit(prepared_dataframe, 'materials', MATERIALS, TrainingConfig(epochs=50))
predictor = Predictor(checkpoint)
# Для общего применения массива — двумерный float32 в порядке predictor.features:
values = predictor.predict(feature_matrix)
```

Высокоуровневый API run и команды README работают как раньше. Генерация предметных признаков и расчёт закупок остаются обязанностью сценария, а не MLP.

Итог: `python -m pytest -q` — 15 passed в текущем CPU-окружении (pytest из /tmp/predictml-test-deps). CLI --help проверен. Итерация 2 завершена; следующая — исправление временного сценария спроса (итерация 3).
