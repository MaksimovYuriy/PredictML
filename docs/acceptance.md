# Приёмка PredictML 0.1

Профиль: Python 3.12, CPU, фиксированные requirements.txt и requirements-dev.txt. Дата проверки — 14 ноября 2026 года. Запуск в Linux/WSL2 не является нативной проверкой Windows.

## Воспроизведение

```bash
python -m venv .venv
# Используйте интерпретатор .venv; команды Windows/Linux приведены в README.
python -m pip install -r requirements.txt -r requirements-dev.txt
python -m pip check
python -m pytest -q
python -m build --wheel --sdist --no-isolation --outdir artifacts/dist
python -m pip install --no-deps PATH_TO_WHEEL.whl
python scripts/acceptance.py --output artifacts/acceptance/scenario
```

Для доказательства независимости wheel установите его в отдельное окружение и запускайте acceptance.py из другой рабочей папки без PYTHONPATH исходного репозитория. Функции работают с установленным predictml; demo извлекает файлы из пакета, а не из соседнего checkout.

Автоматическая программа приёмки выполняет экспорт встроенных примеров, XLSX/лист/предпросмотр, обучение трёх моделей таблицы, прогноз сохранённой версии в новом процессе, обе операции обновления, независимый контроль, экспорт метрик, подготовку ServiceFlow и обучение/применение четырёх предметных моделей. Короткие 3–5 эпох проверяют исполнение пути, а не качество модели на реальных данных.

## Границы результата

Windows: инструкции и workflow .github/workflows/acceptance.yml подготовлены; фактический запуск Windows не заменяется ни Linux/WSL2, ни проверкой доступности wheel. Workflow не считается выполненным до его запуска в CI. Отсутствие Ruby даёт явно отмеченный skip только для исходного Ruby-сравнения.

Программа использует доверенные pickle/joblib-комплекты. Загрузка строго проверяет окружение; CPU-профиль с torch +cpu отличается от ранних экспериментальных окружений без этого суффикса. Старые демонстрационные модели нужно применять в их исходном окружении либо обучить заново в профиле поставки; скрытого изменения manifest нет.

Не подтверждались качество на реальных данных, превосходство MLP, оптимальность рекомендованной цены, реальный PostgreSQL экспорт и многопользовательская нагрузка. Источник рекомендаций цены и консервативные ограничения provenance описаны в transfer-report/updates-contract. Материалы курса и академические главы не входят в эту поставку.

Фактические результаты финальных прогонов дополняются ниже после их завершения; отчёт не подменяет отсутствующие проверки утверждением об успехе.

## Фактически выполнено

- Создано новое venv без system-site-packages: Python 3.12.8, Linux x86-64/WSL2, torch 2.13.0+cpu. Установлены requirements и фиксированные dev-инструменты. `pip check`: No broken requirements found.
- В исходном дереве и затем с установленным wheel из /tmp без PYTHONPATH: 63 passed. XML — artifacts/acceptance/junit.xml.
- Собраны wheel и sdist. Wheel содержит демоданные, не содержит venv/artifacts. Данные UI загружаются из пакета, рабочие файлы создаются в текущей папке.
- scripts/acceptance.py с установленным пакетом вне checkout: passed. Пять версий таблицы, шесть её запусков, по две обученные версии спроса и цены; все четыре предметные модели применены после сохранения.
- Настоящий Chromium 159 через Playwright: XLSX upload, выбор листа, обучение, скачивание CSV, загрузка нового CSV, прогноз и скачивание XLSX — passed, JavaScript errors = []. Снимки training.png/prediction.png и browser.json — artifacts/acceptance/browser.
- Нативная Windows не запускалась. Попытка Linux pip --platform win_amd64 не признана проверкой Windows: resolver применил Linux-маркеры к зависимостям, запросил CUDA/NCCL и завершился ошибкой. Эта попытка не отменяет успешный Linux CPU-профиль, но и не доказывает Windows-совместимость. Отдельные Windows-маркеры tzdata/colorama закреплены; фактическую проверку выполняет подготовленный native CI.

Для повторения браузерной проверки установите requirements-browser.txt и выполните `python -m playwright install chromium`, запустите UI и отдельно `python scripts/browser_acceptance.py --url http://127.0.0.1:8501 --examples examples --output artifacts/browser-check`. Это опциональный приёмочный инструмент, не runtime-зависимость программы. Тестовый сервер после проверки останавливается.

Отчёты установки, freeze, журнал сборки, сквозного сценария и снимки являются локальными артефактами в игнорируемом artifacts/acceptance. Исходные сценарии воспроизведения и CI остаются в репозитории. GitHub workflow подготовлен, но в этой сессии не отправлялся и не запускался.
