# Отчёт о переносе из ServiceFlow

Использованы четыре исходных Python-скрипта train/predict материалов и цены, два Ruby-сервиса подготовки и контракт их обмена CSV/JSON. Исходники сохранены как тестовые эталоны в tests/reference; SHA-256 — [tests/reference/source-manifest.json](../tests/reference/source-manifest.json). Программа не читает ServiceFlow_back во время работы, не требует Rails/Sidekiq/PostgreSQL. Исходный проект не изменялся.

| Было | Стало |
|---|---|
| Ruby + SQL агрегируют завершённые записи | Python-подготовка из четырёх экспортированных CSV |
| Jobs запускают subprocess с фиксированным venv | Общие Python API, CLI и Streamlit |
| Две дублирующиеся MLP с фиксированными признаками | Общая параметризуемая MLP и линейная регрессия, универсальный табличный конвейер |
| Файлы ml/../tmp, перезапись весов | Явные пути, независимые Store, UUID-версии и история SQLite |
| Нормировка отношения спроса по всей истории | demand-v2 прогнозирует количество, масштабирование признаков только по train |
| Одношаговый test трактовался как многомесячный | Отдельная одношаговая оценка и рекурсивное окно от фиксированного origin |
| Разные правила тренда и укороченная история | Одна причинная функция для обучения/рекурсии, полная агрегированная история |
| Текущий месяц принимался за полный | as-of исключает свой месяц целиком |
| Неявные единицы и округление | unit/purchase_step, Decimal, одна закупка на весь горизонт |
| Формульная цена называлась прогнозом | Явная рекомендация и сравнение с прямым правилом |

Контроль переноса: изолированные исходные Ruby-методы сравниваются с Python без БД; старые Python-скрипты сравниваются по весам/метрикам/прогнозам при одинаковом seed. Legacy-parity сохраняет исходные политики для этих проверок. Он не применяется автоматически к исправленной методике.

Новое: загрузка CSV/XLSX, выбор схемы, предобработчик и unknown-category policy, baseline/linear/MLP на одних разделах, early stopping, метрики в исходных единицах, версия/целостность/окружение, независимый контроль, обновления и UI. Синтетика явно обозначена; реальная база и исходные checkpoint в поставку не входят.

Ограничения: реальный PostgreSQL SQL и полный экспорт из действующей БД не выполнялись; корректность SQL сравнения не объявляется доказанной только изолированными тестами. Исторические цены/остатки исходная схема не восстанавливает. Цена учит заданное правило, не оптимальную прибыль. Спрос оценён на одном фиксированном окне, а не на множестве независимых backtest-окон. Доказательств превосходства MLP на реальных данных нет.

Старые комплекты могут не содержать provenance: они пригодны для прогноза при совпадении окружения, но непроверяемое независимое сравнение отклоняется. Повторяемость параллельного обучения не гарантируется. Консервативные правила целостности и сравнения описаны в storage-contract.md и updates-contract.md.
