# Итерация 5: модели, early stopping и корректное сравнение

Реализовано сравнение baseline, линейной регрессии и MLP через общее ядро. Два предметных сценария дают четыре обученных модели: demand MLP/linear и price MLP/linear; baseline и формульное правило — дополнительные ориентиры.

## Общее ядро и обучение

regressors.py обучает LinearRegression, константный baseline и общую PyTorch MLP. Коэффициенты линейной модели сохраняются в общем checkpoint вместе со статистиками и порядком признаков; Predictor применяет MLP/linear/baseline. Старые MLP-checkpoint без model_kind читаются как раньше.

TrainingConfig дополнен patience, min_delta и seed. Общая оптимизация сохраняет лучшие веса по минимальной validation MSE, а остановка происходит после patience проверок без улучшения больше min_delta. Patience считается проверками, не эпохами. Лучшие веса восстанавливаются, даже если последнее состояние хуже. В журнале — validation curve, best_epoch, epochs_ran, stopped_early и время обучения с проверками validation. Проверка test происходит после выбора лучших весов и не участвует в остановке.

Настройки CLI: hidden-sizes, learning-rate, epochs, batch-size, seed, validation-interval, patience, min-delta; disable-early-stopping отключает остановку. Современные команды train-table/compare по умолчанию проверяют validation каждую эпоху, patience=20. Старые train-predict/legacy сохраняют прежние defaults для совместимости. Автоматического подбора гиперпараметров нет.

## Универсальная таблица

train-table теперь обучает все три алгоритма на одном разбиении и одном train-only предобработчике. Baseline — среднее цели только на train. MLP и линейная модель получают одинаковые преобразованные признаки. Цель не масштабируется, все метрики в исходных единицах.

model.joblib сохраняет явно выбранную модель (по умолчанию MLP); --model-kind linear/baseline/mlp выбирает её явно, best выбирает минимум validation MSE. Независимо от этого сохраняются model-mlp.joblib, model-linear.joblib и model-baseline.joblib. В отчёте отдельно указаны selected_model и recommended_model; test не выбирает ни модель, ни параметры.

Табличная схема/предобработчик сохраняются в каждом комплекте. test_predictions.csv содержит одинаковые source_row/actual и колонки prediction_baseline/linear/mlp. Temporal-разбиение с исключением пересекающихся горизонтов остаётся прежним.

## Спрос

`compare materials` обучает MLP и линейную модель с одинаковыми семью причинными признаками, нормировкой и границами train/validation/test. MLP выбирает лучшие веса по рекурсивному прогнозу validation. Линейная модель обучается только на train; её качество validation вычисляется в такой же рекурсии.

Финальная оценка: одна фиксированная точка перед test, прогнозы lead=1/2/3 без подстановки будущих фактов. Last value и mean3 также рекурсивны и используют только историю на origin. Сохранены агрегированные метрики и показатели по каждому lead. Заявление о превосходстве на множестве независимых временных окон не делается.

Файлы material-mlp.pth и material-linear.pth содержат свои коэффициенты/веса, одинаковую схему и историю demand-v2. Их можно применять обычной командой predict materials. Расчёт закупок общий. material_model.pth — копия MLP для совместимости; автоматического подменивания этой модели по test нет. Рекомендованный по validation метод может быть baseline — это честный результат сравнения, а не ошибка.

## Рекомендация цены

`compare price` обучает MLP/linear на одинаковых признаках и временных разделах. Цель обучения по-прежнему price_ratio; для оценки возвращается денежная цена. Validation objective MLP — MSE в денежных единицах после ограничения 85–115%, лучшие веса выбираются именно по этому критерию. Линейная модель и baseline оцениваются с тем же ограничением. Baseline сохраняет текущую базовую цену.

Отдельный ориентир formula напрямую воспроизводит правило из признаков: base_price × (1 + 0.05 × bookings/max_bookings_месяца − 0.03 × first_visit_share). Это рекомендация по заданному правилу, а не прогноз будущей наблюдаемой цены. Формула закономерно может выиграть у моделей: учить известное правило через MLP не обязательно полезно.

Сравнение относится к месячным строкам и воспроизведению правила. Оно не оценивает прибыль, реакцию спроса или качество бизнес-решения. Фактический старый прикладной вывод сохранённых price-mlp/linear.pth остаётся рекомендацией по усреднённым признакам последнего года с прежней дополнительной скидкой непопулярным услугам; эта агрегация и скидка не входят в месячную контрольную оценку. После экспорта признаки доли округлены, поэтому прямая формула может отличаться от исходной метки на копейки.

## Отчёты и метрики

MAE, MSE, RMSE, wMAPE (в процентах) и R² рассчитываются общей regression_metrics. Нулевая сумма абсолютных фактов → wMAPE=null; менее двух фактов или постоянная цель → R²=null. Пустые массивы, несовпадающие длины и не конечные значения отклоняются. Исторический compute_metrics остаётся только для воспроизведения legacy.

Для каждого сравнения сохраняются comparison.csv, comparison_predictions.csv и comparison.html с таблицей, интерактивным выбором модели и графиком «факт/прогноз». Параметры, seed, идентификатор запуска, границы/состав выборок, время и журнал MLP доступны в JSON и HTML. Сервисные сравнения записывают comparison.json; табличный сценарий — report.json. Это идентификатор запуска, а не полноценная система версий: она относится к итерации 6.

Старые тесты переноса и итераций 1–4 сохранены.
