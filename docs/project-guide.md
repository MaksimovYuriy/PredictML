# Навигация по учебному проекту

В репозитории остаются исходники программы, единственная копия примеров, проверочные материалы и документы для разработки пособия. История итераций и результаты конкретных запусков не нужны для сборки программы по главам.

## Путь изучения программы

Начинайте с `config.py`, затем последовательно изучайте `data.py`, `preprocessing.py`, `models.py`, `training.py`, `evaluation.py` и `prediction.py`. После рабочего табличного конвейера переходите к предметным сценариям, сохранению, обновлениям и интерфейсу.

| Файл в predictml | Зачем нужен |
|---|---|
| `config.py` | Настройки обучения, архитектуры, признаки, столбцы и коэффициенты формулы |
| `data.py` | Чтение CSV/XLSX и проверка схемы таблицы |
| `preprocessing.py` | Обучаемые преобразования признаков |
| `models.py` | MLP и единое применение checkpoint разных алгоритмов |
| `training.py` | Разбиение, обучение кандидатов, validation и early stopping |
| `evaluation.py` | Метрики и независимость контрольных наблюдений |
| `prediction.py` | Применение сохранённого табличного конвейера |
| `workflow.py` | Общие пользовательские операции для CLI/UI |
| `updating.py` | Переобучение и продолжение MLP |
| `reporting.py` | CSV/XLSX/HTML-отчёты |
| `demo.py` | Доступ к встроенным примерам и экспорт рабочей копии |
| `cli.py` | Разбор команд и параметров |
| `__main__.py` | Запуск через python -m predictml |
| `__init__.py` | Версия пакета, используемая в метаданных моделей |
| `scenarios/demand.py` | Причинные признаки спроса, рекурсия и временная оценка |
| `scenarios/materials.py` | Расход, остатки, закупка и стоимость |

| `storage/repository.py` | SQLite, транзакции, запуски и версии |
| `storage/bundles.py` | Сериализация, manifest, целостность и совместимость |
| `storage/__init__.py` | Публичные операции хранилища, используемые остальными модулями |

| `ui/launcher.py` | Настройка и запуск локального сервера |

| `compatibility/legacy.py` | Исполняемый адаптер режима legacy-parity |
| `compatibility/materials.py` | Исходный алгоритм относительного спроса для legacy-parity |

| `compatibility/__init__.py` | Объявление пакета совместимости |

Все 29 Python-файлов участвуют в работе, публичном запуске или упаковке. Совместимость не относится к основному учебному маршруту, но нужна для поддерживаемого режима CLI и старых сохранённых моделей. Её удаление означало бы изменение возможностей программы.

## Служебные файлы и генерируемые каталоги

`pyproject.toml` и `MANIFEST.in` определяют устанавливаемый пакет и исходную поставку. `requirements.txt` закрепляет рабочее окружение, `requirements-dev.txt` — инструменты проверки/сборки, `requirements-browser.txt` — необязательную браузерную проверку. README содержит команды запуска; `.gitignore` исключает результаты работы.

Удалены `artifacts/`, `build/`, метаданные `*.egg-info`, исходные `__pycache__` и кэш pytest. В `artifacts` находились результаты запусков, модели и браузерные файлы; для пособия используются воспроизводимые данные и команды, а не эти результаты. Рабочее окружение из `artifacts/acceptance/venv` перенесено в `.venv`, чтобы сохранить возможность запуска. Оно не входит в Git и не является текстом пособия.

`.git` и подключённые служебные каталоги среды `.agents`, `.aws`, `.codex` не являются исходниками программы и не очищаются этой задачей. Результаты будущих обучений и сборок снова появятся по выбранным пользователем путям; они не входят в исходную учебную поставку.

Тесты сохранены по поведению: `test_tabular` — таблицы и предобработка; `test_training` — цикл MLP; `test_evaluation` — метрики; `test_comparison` — одинаковые условия сравнения; `test_demand`/`test_materials` — предметная математика; `test_storage` — версии и транзакции; `test_updates`/`test_control` — обновление и независимость; `test_ui` — экраны; `test_packaging` — экспорт встроенных примеров; `test_saved_compatibility` — прежние joblib; `test_contracts`/`test_serviceflow_boundary`/`test_legacy_models`/`test_legacy_materials` — контроль переноса и исторического режима.

Удалена одна проверка синхронизации двух копий примеров: после устранения дублирования её предмета больше нет. Остальные проверки сохранены. Из тестовых файлов удалены лишние импорты, скопированные неиспользуемые функции/константы и подготовка временных каталогов там, где она не нужна.

Материалы презентаций: `docs/course/presentations/` — семь PPTX по 15 слайдов; `docs/course/source/presentations.json` — редактируемое содержание. `scripts/build_course_materials.py` воспроизводит PPTX/DOCX и текстовые версии тестов из JSON. Перечень тем и файлов — в [решениях по курсу](course/decisions.md).

Полные пособия находятся в `docs/course/manuals/`: разработка, обучение/эксплуатация и карта соответствия слайдам. `scripts/build_course_manuals.py` собирает их из `docs/course/source/manuals-content.json`, кода приложения и пояснений `manual-code-notes.json`. `experiment-reference.json` хранит справочные результаты реального учебного опыта, а `manual-slide-map.json` — связь подразделов со слайдами. `docs/course/practice/*.py` воспроизводит Excel, проверки и эксперимент; весь этот код также напечатан в пособиях.

Сопоставление первого теоретического модуля хранится в `docs/course/source/theory-alignment.json`, полный отчёт — `docs/course/manuals/Сопоставление_модуля_1_теория.docx`. `scripts/align_theory_materials.py` читает авторские оригиналы без изменения. Итоговый тест курса: `docs/course/tests/final-course-bank.json`, студенческий `Итоговый_тест_30_вопросов.docx`, отдельные `Ключи_Итоговый_тест.docx` и текстовые версии вопросов/ответов. Всего теперь 150 тематических и 30 итоговых вопросов.
