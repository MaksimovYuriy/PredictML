# Модуль 2. Тестовые вопросы

В каждом вопросе один правильный ответ из трёх.


## 2.1. Данные, схема и предобработка


1. В CLI и UI получились разные способы обработки пропуска. Где следует исправить архитектуру?

   А) Перенести обработку в общий вычислительный компонент.

   Б) Синхронизировать две реализации вручную в интерфейсах.

   В) Записать в отчёте, что интерфейсы используют разные правила.


2. Указан отрицательный learning_rate. Когда его следует отклонить?

   А) После первой эпохи, если validation не улучшилась.

   Б) При создании и проверке конфигурации, до обучения.

   В) При сохранении, если полученные веса оказались неверными.


3. В housing столбец id содержит уникальные числа. Как поступить в учебной схеме?

   А) Исключить id, если он лишь обозначает объект выгрузки.

   Б) Включить id как numeric, поскольку пропусков в нём нет.

   В) Использовать id вместо district, чтобы избежать кодирования категорий.


4. В XLSX есть листы about и training. Что требуется для обучения?

   А) Считать первый лист и удалить все строки с пропусками.

   Б) Объединить оба листа, чтобы не потерять строки.

   В) Явно выбрать лист с обучающими наблюдениями.


5. В CSV два столбца получили одинаковое имя area. Какой результат соответствует контракту?

   А) Ошибка структуры до начала обучения.

   Б) Сложение значений двух столбцов в один признак.

   В) Автоматический выбор первого столбца с этим именем.


6. В target одна пустая ячейка, в другой строке записано «дорого». Как их обработает программа?

   А) Обе строки исключит как одинаковые пропуски.

   Б) Неизвестную цель исключит; неверное число вызовет ошибку.

   В) Обе ячейки заменит средним значением train.


7. В features случайно указан target. Что должна сделать проверка схемы?

   А) Разрешить его только для линейной регрессии.

   Б) Отклонить конфигурацию до обучения.

   В) Удалить target из test, сохранив его в train.


8. У строки неизвестна цена, но известны все признаки. Где она пригодна?

   А) Для обучения после заполнения цены медианой признаков.

   Б) Для test, поскольку неизвестная цель не меняет веса.

   В) Для последующего прогноза, но не для размеченного обучения.


9. В test появилась категория, которой нет в train. Должна ли она изменить определённые на train типы?

   А) Да, если test содержит больше строк, чем validation.

   Б) Нет, автоматические типы и преобразования учатся на train.

   В) Да, перед вычислением test-метрик схема переопределяется.


10. Когда следует обучать предобработчик относительно разбиения?

   А) До разбиения, если исходная таблица перемешана.

   Б) После разбиения, объединяя train и validation.

   В) После разбиения, используя только train.


11. В общем временном режиме указан горизонт один месяц. Нужно ли программе автоматически сдвинуть произвольный target?

   А) Да, но только если дата указана как datetime-признак.

   Б) Да, каждый числовой столбец сдвигается на один месяц.

   В) Нет, для этого режима цель уже должна быть подготовлена.


12. В новом файле средняя area заметно изменилась. Какие статистики применяются?

   А) Статистики сохранённого обучающего train.

   Б) Средние статистики train и нового файла.

   В) Статистики нового файла, чтобы центрировать его на нуле.


13. На train были north и south; при прогнозе появился west. Что произойдёт в блоке категории?

   А) Будет выбран код наиболее частого района train.

   Б) Будет нулевое кодирование неизвестного значения.

   В) Предобработчик добавит новую обученную категорию автоматически.


14. В исходной таблице три признака, один из них — дата, другой — категория. Как определить input_size?

   А) По ширине матрицы после обученных преобразований.

   Б) По числу столбцов файла вместе с target и исключённым id.

   В) По числу исходных признаков: input_size всегда равен трём.


15. В новой таблице изменили порядок столбцов, сохранив имена и значения. Что ожидается?

   А) Другой результат, поскольку порядок CSV определяет порядок весов.

   Б) Повторное обучение, потому что схема обязательно изменилась.

   В) Тот же результат transform при сохранённой схеме.


## 2.2. Модели, обучение и оценка


1. В checkpoint указано пять признаков, а коэффициентов linear оказалось четыре. Как должен поступить Predictor?

   А) Отклонить несовместимое состояние.

   Б) Дополнить недостающий коэффициент нулём.

   В) Удалить последний признак из новой таблицы.


2. Цели train: 60, 90, 150. Какие значения выдаст табличный baseline двум новым строкам?

   А) 60 и 150.

   Б) 100 и 100.

   В) 90 и 90.


3. Цели test увеличили, не меняя train. Что произойдёт с сохранённым baseline?

   А) Прогноз увеличится вместе со средним test.

   Б) Прогноз останется прежним, test-ошибка может измениться.

   В) Среднее baseline пересчитается по объединённым целям.


4. Для linear в общей форме указали 1000 эпох; обучение заняло долю секунды. Какое объяснение верно?

   А) Число эпох не задаёт способ обучения LinearRegression.

   Б) Программа применила early stopping линейной регрессии.

   В) Линейная регрессия сохранила прежние веса без fit.


5. Почему между скрытыми Linear-слоями используется ReLU?

   А) Чтобы каждый скрытый слой возвращал только одно число.

   Б) Чтобы композиция могла моделировать нелинейную зависимость.

   В) Чтобы признаки автоматически стали одинакового масштаба.


6. В пакете 32 строки, регрессионная цель одна. Какая форма y согласована с выходом MLP?

   А) [32, 32].

   Б) [1, 32].

   В) [32, 1].


7. Зачем zero_grad выполняется перед новым backward?

   А) Чтобы выключить Dropout на обучающем пакете.

   Б) Чтобы не складывать градиенты текущего шага с прежними.

   В) Чтобы вернуть веса к началу текущей эпохи.


8. Какой режим соответствует обычной validation?

   А) train и no_grad, с optimizer.step после оценки.

   Б) eval с backward для проверки ошибок на новых строках.

   В) eval и no_grad, без optimizer.step.


9. Почему лучший state_dict нужно копировать?

   А) Чтобы включить в checkpoint градиенты следующей эпохи.

   Б) Чтобы увеличить размер обучающей выборки.

   В) Чтобы последующие обновления не изменили сохранённые лучшие веса.


10. Validation MSE по проверкам: 10, 6, 7, 8. Какие веса восстановить при остановке?

   А) Состояние со значением 6.

   Б) Последнее состояние со значением 8.

   В) Среднее весов состояний со значениями 7 и 8.


11. validation_interval = 5, patience = 3. Что считает patience?

   А) Три эпохи после последнего обновления весов.

   Б) Три полных запуска разных архитектур.

   В) Проверки без существенного улучшения, не отдельные эпохи.


12. MLP лучше на test, а linear лучше на validation. Как действует предусмотренное правило рекомендации?

   А) Рекомендует MLP по меньшей test MSE.

   Б) Рекомендует linear по validation MSE.

   В) Выбирает более сложную модель при расхождении метрик.


13. Фактическая цель на всех оцениваемых строках равна нулю. Как трактовать пустую wMAPE?

   А) Метрика не определена из-за нулевого знаменателя.

   Б) Нужно заменить факты единицами и пересчитать.

   В) Модель достигла нулевой процентной ошибки.


14. Изменили только test-цели и повторили запуск с тем же seed. Что укажет на утечку?

   А) Изменились обученные веса или выбранный кандидат.

   Б) Изменилась итоговая test MAE.

   В) Изменился столбец actual в тестовом отчёте.


15. На учебных данных y = 3x + 5 linear почти безошибочна. Какой вывод обоснован?

   А) Для такой точности target нужно оставить среди входов.

   Б) Linear гарантированно лучше MLP для любого спроса.

   В) Реализация восстанавливает эту линейную зависимость.


## 2.3. Предметные сценарии и сохранение моделей


1. В service_materials указан неизвестный material_id. Как поступает подготовка?

   А) Считает расход этого материала равным нулю.

   Б) Присваивает ему цену ближайшего известного материала.

   В) Отклоняет несогласованную связь справочников.


2. as_of = 2027-01-15. Какой последний месяц допустим для подготовки полного спроса?

   А) Ноябрь 2026, поскольку декабрь ближе месяца к границе.

   Б) Декабрь 2026.

   В) Январь 2027 с пересчётом на полный месяц.


3. В месяце нет записей из-за сбоя выгрузки. Можно ли обоснованно считать спрос нулевым?

   А) Да, отсутствие строк всегда означает отсутствие услуг.

   Б) Нет, сначала нужно подтвердить полноту источника.

   В) Да, если в соседнем месяце спрос тоже невысок.


4. Лаг услуги A изменился после добавления строк другой услуги B. Что проверить первым?

   А) Группировку истории по service_id при построении признаков.

   Б) Размер шага покупки материалов услуги B.

   В) Число скрытых слоёв общей MLP.


5. Что является целевой переменной основного спроса demand-v2?

   А) Рассчитанная стоимость закупки материалов.

   Б) Отношение к среднему всей доступной истории.

   В) Количество total_bookings за месяц.


6. При рекурсивном прогнозе февраля от декабря какой январский спрос используется в лаге?

   А) Предсказанный на первом шаге.

   Б) Среднее факта и прогноза января.

   В) Фактический январский, открытый после прогноза.


7. Какие условия нужны для сравнения MLP и linear на трёх шагах спроса?

   А) Одинаковое число эпох при разных месяцах test.

   Б) Общие origin, история и оцениваемые будущие месяцы.

   В) Одинаковое время обучения независимо от истории.


8. Для 12 ожидаемых услуг задана норма 2 мл. Какой расход входит в закупочный расчёт?

   А) 12 мл.

   Б) 6 мл.

   В) 24 мл.


9. Расход 9, минимальный запас 2, остаток 4, шаг покупки 3. Сколько купить?

   А) 6.

   Б) 7.

   В) 9.


10. Для трёхмесячной закупки остаток вычли в каждом месяце. Почему это ошибка?

   А) Один и тот же текущий остаток учтён несколько раз.

   Б) Остаток вообще не должен участвовать в закупке.

   В) Остаток нужно прибавлять к каждому месячному расходу.


11. Месячная денежная оценка цены и пользовательский predict дали разные агрегаты. Что проверить?

   А) Агрегацию и дополнительные правила пользовательского применения.

   Б) Только число эпох последнего запуска.

   В) Только наличие одного и того же файла MLP.


12. В новой таблице отсутствует target, но все входы сохранённой схемы есть. Что возможно?

   А) Вычислить test MAE по отсутствующему target.

   Б) Получить прогноз без оценки его ошибки по этому файлу.

   В) Повторно обучить веса без целевых значений.


13. Сохранены только веса MLP. Чего не хватает для корректного табличного применения?

   А) Схемы, обученных преобразований и порядка входов.

   Б) Только значения batch_size новой таблицы.

   В) Только списка test-метрик прежнего запуска.


14. Совпала SHA-256 чужого pickle с его manifest. Что это подтверждает?

   А) Независимость обучающих данных от будущего контроля.

   Б) Безопасность произвольной загрузки недоверенного pickle.

   В) Целостность относительно этого manifest, но не безопасность источника.


15. После нового обучения появилась новая версия. Что должно случиться с прежней?

   А) Она удаляется после успешной регистрации новой.

   Б) Она остаётся неизменной и доступной по своему ID.

   В) Её payload заменяется новыми весами с прежним ID.


## 2.4. Обновление, интерфейсы и проверка программы


1. Нужно добавить новый способ запуска обучения. Как использовать ядро?

   А) Скопировать цикл обучения в обработчик новой команды.

   Б) Вызвать существующую операцию workflow из новой оболочки.

   В) Считывать результат последнего UI-запуска вместо обучения.


2. Нужно обновить линейную модель по новой размеченной таблице. Какая операция поддерживается?

   А) Fine-tune с прежними коэффициентами.

   Б) Retrain.

   В) Смена epochs без запуска операции.


3. Что определяет fine-tune в программе?

   А) Любое обучение на большем наборе строк.

   Б) Любое обучение с меньшим числом эпох.

   В) Начало с весов сохранённой MLP при фиксированных компонентах.


4. При fine-tune средняя area нового набора изменилась. Что происходит с предобработчиком?

   А) Применяются прежние обученные преобразования.

   Б) Предобработчик пересчитывается только для числовых признаков.

   В) Средние пересчитываются по новому набору без смены версии.


5. Почему fine-tune не равен точному возобновлению прежнего Adam?

   А) Adam превращается в LinearRegression после загрузки.

   Б) Сохранялись веса, но создаётся новый оптимизатор без прежних моментов.

   В) При загрузке обязательно меняется число скрытых слоёв.


6. При retrain изменили target и набор признаков. Как учитывать результат?

   А) Как прогноз исходной версии без регистрации нового результата.

   Б) Как обычное продолжение той же модели с прежним семейством.

   В) Как новую модель с другой схемой задачи.


7. У родителя test содержит старые строки, у обновления — другие. Достаточно ли сравнить их MAE?

   А) Да, если размеры двух test совпадают.

   Б) Да, если обе MAE выражены в рублях.

   В) Нет, нужен общий независимый размеченный контроль.


8. В контроль скопировали обучающие X, но исправили y. Будут ли строки независимыми?

   А) Нет, изменение меток не скрывает повторные наблюдения.

   Б) Да, новая цель делает наблюдение новым объектом.

   В) Да, если файл переименован и заново сохранён.


9. Модель использовала временные цели до июня включительно. Какой контроль соответствует правилу хронологии?

   А) Наблюдения после всех ранее использованных целей.

   Б) Случайные строки из тех же использованных месяцев.

   В) Любые строки с новым индексом, в том числе из мая.


10. У родительской модели нет полного provenance. Что означает отказ сравнения?

   А) Все будущие данные обязательно пересекаются с обучением.

   Б) Модель технически не может выдавать числовой прогноз.

   В) Независимость контроля для этой цепочки не подтверждена.


11. Fine-tune обучали на новом наборе. Относительно каких данных проверять контроль?

   А) Только последних тестовых строк родителя.

   Б) Только нового набора последнего обновления.

   В) Нового набора и наследованной истории использованных данных.


12. В UI поменяли epochs, но не нажали кнопку обучения. К чему относятся старые метрики на экране?

   А) К последнему выполненному запуску.

   Б) К следующей версии, которая появится после закрытия формы.

   В) К новым настройкам, применённым автоматически.


13. Пользователь выбрал каталог зарегистрированной версии как место экспорта. Что правильно?

   А) Разрешить замену при более свежей дате отчёта.

   Б) Не допустить перезаписи неизменяемой истории.

   В) Заменить старый payload таблицей прогноза.


14. Какой тест лучше проверяет отсутствие использования test при обучении?

   А) Проверить, что у checkpoint есть имя test_metrics.

   Б) Изменить только test-ответы и проверить неизменность выбранных весов.

   В) Проверить, что в каталоге появились три файла.


15. Зачем запускать установленный wheel из другой папки?

   А) Чтобы обнаружить зависимость от файлов соседнего checkout.

   Б) Чтобы заменить проверку нативной Windows запуском в WSL.

   В) Чтобы автоматически подтвердить качество на реальных данных.
