# Модуль 3. Тестовые вопросы

В каждом вопросе один правильный ответ из трёх.


## 3.1. Подготовка данных и обучение моделей


1. Какой вопрос подходит для учебного сравнения алгоритмов?

   А) Какой алгоритм лучший независимо от данных и метрики?

   Б) Каковы ошибки linear и MLP на заданной цели при одинаковых условиях?

   В) Как доказать заранее, что MLP точнее любого baseline?


2. Что обязательно отметить в паспорте housing.csv?

   А) Только максимальное число эпох MLP.

   Б) Только имя победившего алгоритма.

   В) Синтетическое происхождение, признаки, цель и единицы.


3. Какой файл следует оставить для независимой оценки обновлений?

   А) housing_update.csv, на котором выполняется fine-tune.

   Б) housing_new.csv без известных целей.

   В) housing_control.csv.


4. В housing.xlsx открыт лист about. Как исправить постановку загрузки?

   А) Выбрать лист training и проверить таблицу.

   Б) Назначить первую строку about числовой целью.

   В) Увеличить эпохи, чтобы модель распознала служебный лист.


5. Auto определил тип даты как categorical. Что делать в описываемой схеме?

   А) Назначить дату target, чтобы сохранить её порядок.

   Б) Явно выбрать datetime для календарных преобразований.

   В) Оставить auto, поскольку дата всегда распознаётся автоматически.


6. Временные части упорядочены, но признак содержит будущую выручку. Что это означает?

   А) Утечка сохранилась, несмотря на правильный split.

   Б) Признак допустим, если предварительно нормализован.

   В) Утечки нет, поскольку строки test идут после train.


7. Baseline выдаёт одно число всем строкам. Что проверить прежде всего?

   А) Совпадение с y_train.mean и независимость от test.

   Б) Совпадение с медианой нового файла без target.

   В) Наличие ненулевого Dropout в baseline.


8. Linear обучилась за 0.5 секунды при указанном максимуме 1000 эпох. Как оценить ситуацию?

   А) Считать запуск неполным до достижения времени обучения MLP.

   Б) Повторить linear с большим patience для увеличения длительности.

   В) Проверить алгоритм, данные и метрики: эпохи не управляют её fit.


9. Две модели имеют одинаковую test MAE, но разное время fit. Что допустимо заключить?

   А) Более медленная модель точнее, поскольку дольше обучалась.

   Б) По этой оценке качество близко, стоимость обучения различается.

   В) Более быстрая модель не обучалась по заданным данным.


10. Хотим исследовать влияние learning_rate. Как составить первый опыт?

   А) Одновременно менять split, слои и seed без протокола.

   Б) Выбирать learning_rate по самому удачному test-запуску.

   В) Менять его при фиксированных данных и остальных записанных условиях.


11. epochs = 1000, epochs_ran = 180, best_epoch = 160. Какой прогноз выдаёт сохранённая MLP?

   А) Прогноз весов лучшей 160-й эпохи.

   Б) Средний прогноз всех 180 эпох.

   В) Прогноз обязательно последних весов 180-й эпохи.


12. patience = 4 и validation_interval = 5. Четыре чего ожидает остановка?

   А) Четырёх отдельных обучающих пакетов.

   Б) Четырёх проверок без существенного улучшения.

   В) Четырёх эпох независимо от интервала validation.


13. После двадцати подборов по test выбрана лучшая архитектура. Какова роль этого набора теперь?

   А) Он становится обучающим и должен использоваться вместо train.

   Б) Он фактически участвовал в выборе; нужна новая независимая оценка.

   В) Он остаётся независимым, если на нём не было backward.


14. Что нужно записать после обучения для воспроизведения результата?

   А) Данные, схему, настройки, окружение и ID версии.

   Б) Только дату запуска и название MLP.

   В) Только график с наименьшей ошибкой.


15. MLP не улучшается. Какое действие обоснованно до усложнения архитектуры?

   А) Добавить target в признаки, чтобы снизить loss.

   Б) Смешать test с train, сохранив прежний отчёт test.

   В) Проверить данные, цель, доступность признаков и масштаб.


## 3.2. Прогнозирование и предметное применение


1. В Store есть несколько моделей с похожими датами. Как выбирать для прогноза?

   А) По ID, проверив задачу, схему и алгоритм.

   Б) По наибольшему размеру payload независимо от цели.

   В) По самому короткому имени файла.


2. Для выбранной housing-модели отсутствует обязательная area, но имеется price. Что делать?

   А) Исправить входной файл: наличие цели не заменяет признак.

   Б) Удалить area из весов перед прогнозом.

   В) Использовать price вместо area в сохранённой схеме.


3. В новой таблице переставлены столбцы и добавлена служебная колонка. Как ожидается применение?

   А) Весам назначаются столбцы в новом физическом порядке.

   Б) Служебная колонка автоматически становится новым признаком.

   В) Нужные входы выбираются по именам; лишняя колонка игнорируется.


4. Новая таблица имеет другую среднюю area. Что сохраняется при обычном predict?

   А) Только веса, а нормировка пересчитывается.

   Б) Нормировка, обученная на прежнем train.

   В) Только имена признаков, все остальные параметры обучаются заново.


5. Неизвестный district прошёл предусмотренное кодирование. Какой вывод допустим?

   А) Файл технически обработан; качество на новой категории ещё не доказано.

   Б) Категория стала эквивалентной самому частому району train.

   В) Модель автоматически научилась оценивать новый район.


6. Для чего в условиях прогноза сохраняют ID версии?

   А) Чтобы автоматически сделать фактические цели известными.

   Б) Чтобы повторно применить именно ту же модель.

   В) Чтобы обучить версию заново при чтении файла.


7. Получены правдоподобные числа для housing_new без target. Можно ли вычислить их реальную MAE?

   А) Да, по расстоянию до среднего самих прогнозов.

   Б) Да, записав прогноз в колонку actual.

   В) Нет, для MAE нужны сопоставимые фактические значения.


8. При as_of = 2027-01-01 какие январские данные входят в подготовку спроса?

   А) Январь включается с весом, пропорциональным прошедшим дням.

   Б) Никакие: январь является исключаемым месяцем границы.

   В) Все завершённые записи января, найденные в файле.


9. Для мартовского прогноза от декабря на три шага откуда берётся февральский лаг?

   А) Из предыдущего предсказанного шага.

   Б) Из исправленной test-цели февраля.

   В) Из фактической февральской выгрузки, открытой после origin.


10. В сохранённой истории исправили старые месячные факты и передали их в обычный predict. Что ожидается?

   А) Тихая замена истории с сохранением прежних метрик.

   Б) Отказ от незаметной замены истории; нужно явное обучение или обновление.

   В) Автоматическая правка старых весов в той же версии.


11. Почему нельзя подменить метрики трёхшаговой рекурсии одношаговой оценкой?

   А) В рекурсии нельзя вычислить MAE по фактам.

   Б) Одношаговая оценка всегда использует другой алгоритм.

   В) Во втором и третьем шагах различается доступная история.


12. Норма задана в мл, а остаток — в литрах. Что требуется до закупочного расчёта?

   А) Сложить значения как числа, затем округлить.

   Б) Изменить learning_rate до совпадения сумм.

   В) Согласовать единицы и цену соответствующей единицы.


13. Расход 7, минимальный запас 2, остаток 3, шаг 4. Сколько требуется купить?

   А) 4.

   Б) 8.

   В) 6.


14. Ценовая модель хорошо восстанавливает формульную цель. Что это подтверждает?

   А) Оптимальность будущей рыночной цены для максимальной прибыли.

   Б) Гарантированный рост спроса после применения рекомендации.

   В) Способность воспроизводить правило в условиях проверенного набора.


15. prediction совпала с prediction_linear для каждой строки. Что проверить прежде всего?

   А) Была ли linear выбранной моделью общего столбца prediction.

   Б) Попал ли target обязательно в число признаков.

   В) Скопированы ли все факты независимо от выбранной модели.


## 3.3. Сравнение алгоритмов, обновление и выводы


1. У MLP и linear одинаковая цель, но разные test-строки. Как трактовать разницу MAE?

   А) Её нельзя приписать только алгоритму без одинаковых условий.

   Б) Меньшая MAE однозначно доказывает превосходство алгоритма.

   В) Разница исчезает, если округлить прогнозы до целых.


2. Нужно сравнить ошибку количества услуг и ошибку цены в рублях. Как оформить результаты?

   А) Отдельно по задачам и единицам, с одинаковыми ориентирами внутри задачи.

   Б) Усреднить две MAE в одну итоговую ошибку проекта.

   В) Перевести все числа в проценты без проверки знаменателя.


3. Модель A имеет меньшую MAE, но большую RMSE, чем B. Что следует сделать?

   А) Объявить B лучшей только из-за большего времени обучения.

   Б) Учесть стоимость крупных ошибок и заранее выбранный критерий.

   В) Объявить A лучшей независимо от характера ошибок.


4. Остаток определён как prediction − actual и равен +12. Что это означает?

   А) Среднюю относительную ошибку 12 процентов.

   Б) Завышение прогноза на 12 единиц цели.

   В) Занижение прогноза на 12 единиц цели.


5. Общая MAE мала, но одна услуга систематически недопрогнозируется. Что включить в анализ?

   А) Только общий средний показатель по всем строкам.

   Б) Только число эпох, поскольку группы уже учтены в среднем.

   В) Ошибки по услугам и характерные наблюдения.


6. Linear оказалась точнее MLP на почти линейной синтетике. Какой вывод соответствует опыту?

   А) Linear лучше в проверенных условиях; универсальный вывод преждевременен.

   Б) Линейная регрессия доказанно лучше всех нейросетей.

   В) Эксперимент следует повторять, пока MLP не победит на test.


7. Для нескольких seed получились заметно разные результаты MLP. Как их представить?

   А) Свести результаты и разброс по заранее заданному плану.

   Б) Усреднить веса любых архитектур без описания процедуры.

   В) Оставить только seed с лучшей test-ошибкой.


8. Как программа формирует итог нескольких seed?

   А) Seed не влияет на MLP, поэтому сводка не требуется.

   Б) Команда compare автоматически усредняет все прежние seed.

   В) Запуски сохраняются отдельно; общую сводку составляют явно.


9. У fine-tune снизилась внутренняя test MAE по сравнению с родителем. Достаточно ли этого для вывода об улучшении?

   А) Да, независимо от того, какие строки входили в test.

   Б) Да, если обновление содержит меньше эпох, чем родитель.

   В) Нет, версии нужно оценить на общем независимом контроле.


10. Контроль многократно использовали для подбора обновления. Какова его фактическая роль?

   А) Он становится эталоном, который можно добавить к каждому train.

   Б) Он участвует в выборе; для нового подтверждения нужен другой контроль.

   В) Он остаётся независимым, пока не вызывали backward.


11. Схемы версий совпали, но для родителя неизвестны обучающие наблюдения. Что корректно?

   А) Считать контроль независимым только по совпадению схем.

   Б) Заменить неизвестный provenance текущим контрольным файлом.

   В) Отказать в подтверждении независимого сравнения.


12. В control повторены прежние признаки, но изменены метки. Почему сравнение отклонено?

   А) Любое изменение метки технически запрещено в новой таблице.

   Б) Сравнивать можно только файлы с одинаковым именем.

   В) Provenance распознаёт повторное наблюдение по признакам.


13. Что делает compare-versions в описываемом процессе?

   А) Дообучает каждую версию до наименьшей контрольной ошибки.

   Б) Оценивает загруженные версии на общем контроле без fit.

   В) Автоматически заменяет прежнюю лучшей контрольной версией.


14. Прямой расчёт формулы точнее MLP по цели, созданной той же формулой. Как это объяснить?

   А) Формула непосредственно восстанавливает правило, которое модель аппроксимирует.

   Б) Это доказывает бесполезность ML для всех задач спроса.

   В) Это обязательно означает неисправность сохранённых весов.


15. Какой итоговый вывод наиболее обоснован?

   А) A лучше всех моделей, поскольку в одном опыте имела меньшую MAE.

   Б) На заданном наборе и контроле A лучше baseline по MAE; перенос на реальные данные не проверен.

   В) A улучшит прибыль, поскольку её формульная цена ближе к target.
