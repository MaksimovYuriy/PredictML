# Универсальная таблица: контракт итерации 4

Это дополнительный сценарий, независимый от контрактов материалов/цены ServiceFlow. Ядро находится в predictml/tabular; CLI вызывает его функции.

## Чтение

CSV: UTF-8, запятая, заголовок. XLSX: именованный лист; если лист не выбран, первый. Заголовки — уникальные непустые строки, таблица содержит хотя бы одну строку. Можно получить список листов и предпросмотр с количеством строк, столбцами и пропусками. Чтение целиком в память; потоковая обработка не предусмотрена.

## Конфигурация JSON

```json
{
  "target": "price",
  "features": ["area", "district", "built_at"],
  "exclude": ["id"],
  "types": {"area": "numeric", "district": "categorical", "built_at": "datetime"},
  "seed": 42
}
```

- target обязателен: числовая конечная цель. Строки с отсутствующей целью исключаются с отчётом, цель никогда не заполняется. Нечисловые значения или infinity — ошибка, а не пропуск. Требуется минимум 10 размеченных строк.
- features — уникальный непустой список. Если не задан, используются все столбцы кроме цели и exclude. Цель и исключённые столбцы не могут одновременно быть признаками.
- exclude — список известных столбцов для исключения.
- types — явные numeric/categorical/datetime для выбранных признаков. Остальные типы определяются только по train: все известные значения преобразуются в числа → numeric, иначе categorical. Даты автоматически не угадываются. Если train-столбец полностью пуст, его тип нужно указать явно. При изменении цели/признаков требуется обучение новой модели.
- seed задаёт воспроизводимое случайное разбиение и инициализацию MLP. По умолчанию 42. Без temporal доли train/validation/test — 60/20/20, с округлением количества train и validation вниз.

Рекомендуется задавать types явно, особенно для идентификаторов категорий и чисел с ведущими нулями. Типы здесь семантические: например numeric принимает числа и строки, однозначно преобразуемые в число. Categorical сравнивается по строковому представлению; изменение написания считается другой категорией.

## Предобработка

Единый сохраняемый sklearn-конвейер обучается только на train, после исключения отсутствующей цели и разбиения:

- numeric: медиана train для пропусков, StandardScaler по train. Для явно числового полностью пустого train-столбца заполнитель 0, столбец сохраняется.
- categorical: отдельное значение для пропуска, OneHotEncoder с handle_unknown=ignore. Неизвестная категория кодируется нулями соответствующего блока и не добавляется в словарь. Настоящие значения имеют внутренний префикс value:, поэтому строковая категория не совпадёт со служебным значением пропуска.
- datetime: ISO-даты/время без часового пояса; год, месяц, день, день недели, час, минута, sin/cos месяца. Эти числовые признаки проходят тот же train-only imputer/scaler. Точность секунд и часовые пояса не моделируются; зону нужно нормализовать заранее.

На прогнозе схема не меняется. Выбираются сохранённые имена в сохранённом порядке; внешняя перестановка столбцов безопасна. Отсутствующие признаки и неверные числа/даты — понятная ошибка со столбцом. Лишние столбцы игнорируются. Пропуски признаков допустимы. Размер MLP вычисляется после предобработки, включая one-hot и календарные столбцы.

## Общий временной режим

Дата сама по себе не включает прогнозирование. temporal задаётся явно:

```json
{
  "target": "next_month_count",
  "features": ["capacity"],
  "temporal": {
    "time_column": "origin",
    "frequency": "MS",
    "horizon": 1,
    "target_definition": "Количество за следующий месяц, уже присоединено к строке даты origin",
    "available_features": ["capacity"]
  }
}
```

time_column — дата момента прогноза. Источник заранее готовит цель для horizon периодов после неё и только признаки, известные в этот момент; приложение не сдвигает цель и не рассчитывает лаги автоматически. available_features должен явно перечислить каждый выбранный признак. Это декларация доступности, а не автоматическая проверка бизнес-происхождения данных.

frequency — положительная частота pandas, например D или MS; даты должны соответствовать её календарным границам. horizon — положительное целое. Нужны минимум 10 разных дат origin. Все строки одной даты (в том числе разных объектов) попадают в один раздел. Границы определяются по 60/20/20 уникальных дат. Из train и validation удаляются строки, у которых дата известности цели origin+horizon×frequency достигает начала следующего раздела. В отчёте явно указано число удалённых строк. При недостаточной истории после исключения выдаётся ошибка.

Групповые лаги здесь не создаются; их должен предоставить источник причинным способом. Автоматическая рекурсия 1–3 месяцев по-прежнему доступна только в сценарии demand-v2.

## Артефакты и API

train-table сохраняет model.joblib (веса, обученный предобработчик, схема и отчёт), schema.json, report.json, test_predictions.csv. Нормировка цели не применяется; отчёт и прогнозы в исходных единицах. Отчёт содержит исключённые цели, seed, параметры, строки разбиений и метрики test. source_row — нулевой номер исходной строки данных, без заголовка; это не значение пользовательского id.

predict-table загружает model.joblib без обучения и экспортирует source_row/prediction в CSV или XLSX. Загружать можно только доверенный joblib: он использует pickle. С итерации 6 высокоуровневый train-table регистрирует версии в SQLite и сохраняет manifest-комплекты. Плоский model.joblib — совместимая копия последнего результата; архивные версии доступны через ID. Политика совместимости — в storage-contract.md. Дообучение относится к итерации 7.

```python
from predictml.tabular.io import read_table, preview, sheets
from predictml.tabular.application import train_table, train_file, TabularModel, predict_file

model, test_predictions = train_table(frame, config)
model.save('artifacts/run/model.joblib')
loaded = TabularModel.load('artifacts/run/model.joblib')
values = loaded.predict(new_frame)
```

С итерации 5 train-table сравнивает baseline (среднее train), линейную регрессию и MLP на одном предобработчике и разбиении. Сохраняются model-mlp.joblib, model-linear.joblib, model-baseline.joblib и выбранный model.joblib; --model-kind best выбирает по validation MSE. В отчёте — метрики всех алгоритмов, рекомендованная и явно выбранная модель, время и журнал early stopping MLP. Добавлены comparison.csv, comparison_predictions.csv и comparison.html.
